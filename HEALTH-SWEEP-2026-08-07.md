# Success-on-empty health sweep — 2026-08-07

Fleet-wide adversarial sweep for the recurring failure shape: **health reported from
operation success while the operation returned nothing** (the shape behind the S1
34-day starvation, the ACE freshness blindspot, and two prior instances).
5 finder agents (tsr workers / s2 emit + heartbeat / TAT monitors / TAT generators /
box container-level), 49 candidates, every one adversarially verified (verifiers were
instructed to REFUTE if any other standing mechanism catches the starvation).

**Verdict: 37 CONFIRMED / 12 refuted.** Notable refutations (the standing defenses
work): the intensity/ACE b-deck candidates are covered by the 2026-08-04 btk-mtime
discriminator; two s2 emit candidates were fixed by 52903c7; HAFS starvation is
bounded by ens_watchdog + the dead-man render gate.

**The convergence**: a majority of confirmed TAT-side fixes are one-line
`scripts/freshness_probe.py` extractor swaps — rows gate on `generated_utc`-style
RENDER stamps that re-tick on empty runs, when the same JSON already carries an
honest DATA field (`date`, `windows.30d.end`, `clips[*].last_frame`, `as_of`,
min-across-members). The worker-side confirmed set needs real (small) code: meso
frame-progress gating, floater manifest honesty, a guidance heartbeat that exists,
hafs empty-listing corroboration, s2 lanes without any data-advance monitor.

Fixes below are the verifiers' smallest-change suggestions — none applied
(report-only, per Andrew's instruction).
